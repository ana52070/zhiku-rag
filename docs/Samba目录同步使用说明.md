# Samba 目录增量同步

## 使用方式

1. 打开工作台的「目录同步」，输入管理员访问令牌，点击「新建同步任务」。
2. 粘贴目标共享地址，如 `\\192.168.30.10\资料\技术组`，或分别填写主机、共享名与相对子目录。RAG 主动连接已有共享，不搭建 Samba 服务、不要求提前挂载。
3. 填写只读共享账号及密码，点击「测试连接」。域账号可写成 `域\用户名`。密码加密保存，编辑时留空保留原密码。
4. 选择目标知识库及子目录。源下级目录会在此位置下自动建立。不同任务必须使用互不重叠的目标目录。
5. 设置每日、每周、每隔若干小时或五字段 Cron，填写 IANA 时区，点击「预览执行时间」。例如 `0 2 * * *` 表示所选时区每天 02:00；`0 3 * * 1-5` 表示工作日 03:00。
6. 保存任务。可先关闭定时执行，使用「立即同步」检查结果，再启用定时。执行记录显示新增、更新、跳过、删除、失败及逐项错误。

## 合并与删除规则

文件相对路径标识来源，SHA-256 标识内容。未变文档不重复解析或生成向量。修改先准备完整文本和向量，再以事务更新原文引用、文档和索引，文档 ID 保持不变；失败保留旧版本。首次目标同路径同名文件会自动接管；多份同名文件报冲突，需先人工整理。

共享目录是唯一权威来源。人工移动、删除或停用同步文档后，下一轮恢复来源状态。源文件消失后，仅删除该任务关联的文档；手动上传且未接管的其他文件保留。所有文件处理成功后再次完整扫描，复核目录未变化才执行删除。任何扫描或读取错误都取消本轮删除。

源改名按旧路径删除、新路径新增处理；不承诺保留改名文件的 ID。不提供历史版本库或 Office 内容级合并。空知识库文件夹保留。删除任务保留当前知识库文档，只解除来源映射并删除执行记录。

已有同步映射时禁止修改源根目录和目标位置，需新建任务，避免配置变更触发意外删除。凭据、时间和启停可编辑。

## 调度与运行

当前是单 Rust 实例调度，每 10 秒检查到期任务；同时只运行一个同步任务，防止任务与模型配置、上传、重建或目录管理并发写入。网页遇到忙状态会提示稍后重试。停用定时不影响「立即同步」。服务业务暂停时不启动新同步，已启动任务继续完成。

重启后标记中断的执行记录为失败，已启用任务补执行一次；错过多个执行点不连续补跑。间隔从本轮开始时间计算。执行记录接口返回最近 100 条，数据库保留历史记录。

## 限制

- 支持 TXT、Markdown、PDF、DOCX、XLSX、PPTX、CSV，单文件 50 MiB。忽略 `~$` 开头的 Office 锁文件，不跟随符号链接和重解析点。
- 根目录必须可列举，递归访问全部扫描目录且读取所有支持文件；任一处权限不足将取消整轮扫描。超过 64 层目录或 100000 条目取消扫描。
- 为准确判断内容变化，每次扫描读取支持文件计算哈希；删除前复核再读取一次。增量节省解析与 embedding 成本，不承诺只传输变化的文件。大量文件的网络与扫描耗时需要实际环境测量。
- SMB 使用 2/3 协议库，旧 SMB1-only 共享不在本版范围。域环境采用账号密码认证；复杂 DFS/Kerberos 需单独验证。
- 用户名与密码均为空时使用显式匿名会话。匿名共享不支持 SMB 消息签名与加密；该兼容设置仅应用于本请求的匿名会话，账号连接保持原库默认签名要求。
- 实际 Samba 地址、权限、网络、文档质量和 GPU embedding 耗时以现场联调为准；测试替身只证明同步逻辑。

## 部署配置

`deploy/docker-compose.yml` 中 Rust 与 Worker 必须设置同一个 `RAG_WORKER_TOKEN`，管理员另设 `RAG_ADMIN_TOKEN`。在被 Git 忽略的 `.env` 中配置，令牌不能相同，也不能写进仓库；Worker 不对宿主机发布端口。

```dotenv
RAG_ADMIN_TOKEN=<管理员独立随机令牌>
RAG_WORKER_TOKEN=<内部独立随机令牌>
```

Rust 中的同步接口需要管理员令牌；Worker `/smb/*` 需要 `X-Worker-Token`。不要将内部令牌填到网页或 MCP 客户端。MCP 保持原有知识库只读 Key。

先构建 Linux `rag-core` 并更新 `deploy/bin/rag-core`，再执行：

```bash
docker compose -f deploy/docker-compose.yml up -d --build rag-worker rag-core
```

发布前暂停 RAG 写入并备份完整数据目录（原文件、数据库、加密密钥一起保存）、Compose、环境配置及旧镜像。新增表会自动创建，不重建既有向量。恢复旧服务之前必须恢复完整备份，因为旧二进制无法识别同步版原文件引用。

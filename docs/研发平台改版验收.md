## 本地证据

- `python -m unittest discover -s tests -q`：32 项通过。
- `python -m tests.browser_smoke`：原有上传、索引、预览、检索、暂停恢复、启用禁用和删除流程通过；页面无脚本错误。
- `python -m tests.browser_catalog`：公司原图加载、管理员鉴权、两层子文件夹、定向上传、带令牌下载、跨库移动、Key 创建/范围修改/撤销、明文关闭后清除通过。
- 浏览器五个页面在 1440、1024、768、375、320 像素宽度无横向溢出；检查桌面目录、Key 页及移动端截图。
- 真实官方 MCP 客户端：两个不同 Key 并发查询均只能取得自己的库，不能读取另一库；撤销后请求返回 401。
- 非空旧数据库升级：保留文件 ID 与向量，重复初始化不重复迁移，外键检查通过。
- 短期下载链接：单文件授权，不暴露 Key，过期、篡改目标文件 ID、撤销后失效。

本地模型使用外部接口替身，不证明真实语义召回质量。VPS 的真实模型、现有资料和 OpenClaw 连接另行记录。

## VPS 升级步骤

1. 确认 `/root/zhiku-rag` 工作树干净，systemd 服务为 active。
2. 数据目录和 OpenClaw 配置分别备份，保留旧版本 Git 提交。
3. 更新已同步 GitHub 的代码，沿用 systemd 部署方式。
4. 建立独立管理员令牌，创建 OpenClaw 全库只读 Key；按已安装 OpenClaw 2026.9.9 Schema 的 `mcp.servers.zhiku-rag.headers.Authorization` 配置。
5. 复核原文件、ID、索引数量及原向量保持不变，检查 MCP 检索、引用下载与 Key 权限。
6. 凭证仅保存到本地被 Git 忽略的 `data/`，不写入本验收记录或提交。

# 研发知识平台实现计划

目标：为研发部提供按知识库和目录管理资料、按 API Key 授权的浅蓝白色工作台。

架构：沿用 FastAPI、FastMCP、SQLite 和原生前端。目录为逻辑资源；原文件与索引保持稳定 ID；检索权限由服务端执行。

方案：`docs/改版方案.md`。本次在当前会话逐项执行，不委派其他代理。

## 任务一：目录及迁移

- [ ] 在 `tests/test_libraries.py` 验证已有文件默认归库、同库子文件夹、移动文件保留索引、拒绝跨库父节点和非空删除。
- [ ] 运行 `python -m unittest tests.test_libraries -v` 确认新增行为失败。
- [ ] 修改 `app/storage.py` 进行幂等数据库升级；在 `app/catalog.py` 定义库和目录管理。
- [ ] 修改 `app/service.py`、`app/main.py` 接入库、目录和可选检索范围；运行新测试及已有测试。

## 任务二：API Key 权限

- [ ] 在 `tests/test_keys.py` 验证 Key 摘要保存、撤销生效、授权更新、禁止管理写操作、禁止跨库读取和下载。
- [ ] 用真实 MCP 客户端验证 Key A 不能取得库 B 的列表、片段、全文。
- [ ] 实现 `app/access_keys.py`，更新请求鉴权，保留旧环境令牌兼容。
- [ ] 运行 `python -m unittest discover -s tests -v`；测试使用临时数据库及外部模型替身。

## 任务三：UI 和交付

- [ ] 改版 `app/static/index.html`、`style.css`、`app.js`，增加目录导航和 Key 管理，保留现有元素 ID 与功能。
- [ ] 验证浏览器上传、目录移动、Key 创建撤销、预览、下载、检索、配置、暂停和移动端布局；检查截图及页面错误。
- [ ] 更新 README 与验收记录；检查 Git diff 和待提交文件；提交并同步 GitHub。
- [ ] VPS 联调时先确认部署方式并备份数据库，再更新代码；不得执行旧部署脚本中的覆盖数据库操作。

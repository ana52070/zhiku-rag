# 研发部知识平台改版方案

## 已对齐的目标

- 浅蓝白色管理台；使用 UI UX Pro Max 的通用交互规则，保留原生 HTML/CSS/JavaScript 与单服务部署。
- 以知识库为单位管理文件；库内支持网页新建子文件夹、上传、移动和删除。原文件继续使用随机 ID 保存，目录由数据库表达，避免目录名变化破坏索引和链接。
- MCP API Key 可授权一个或多个知识库；第一版现有 OpenClaw 使用覆盖全部知识库的 Key。
- 授权作用于检索、列表、原文及下载；管理员凭证与检索凭证独立。Key 明文仅创建时返回，数据库保存摘要；支持更新范围与撤销。
- 保留已有文件 ID、向量、模型配置与下载地址；默认归入默认知识库，等待维护人员整理。

## 接口与安全边界

管理员通过 `/api/libraries`、`/api/folders`、`/api/keys` 管理资源。文档新增 `library_id`、`folder_id`；目录使用同库父节点，拒绝跨库父节点和非空目录删除。MCP 增加可选 `library_id`，缺省查询当前 Key 所有获授权的库；调用者不能用参数扩大权限。

请求级权限使用上下文隔离，避免并发 MCP 客户端串用授权。客户端携带 `Authorization: Bearer <API Key>`。旧环境 MCP 令牌保留兼容，仍拥有全部库权限；配置新 Key 后匿名 MCP 请求必须拒绝。

下载接口允许管理员或获授权 Key 读取；管理网页下载携带管理凭证。MCP 返回针对单文件的签名下载链接，10 分钟有效，并实时校验 Key 撤销和范围变化，链接中不包含 API Key。

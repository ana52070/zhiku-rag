# 工程部手册独立采集与同步

## 工作方式

独立采集容器每周一 02:00（Asia/Shanghai）访问工程部手册网页，首次启动立即采集。失败保留已发布版本，每小时重试。知识库使用本地只读来源，每小时检查一次，内容没有变化时跳过文档解析与 embedding。

采集器代码位于 `collectors/engineering_handbook/`，不调用知识库上传接口、不持有管理员或 MCP Key。Worker 只读挂载采集目录，Rust 核心管理索引、来源映射及同步记录。旧 Samba 同步任务继续兼容。

## 保存内容

- `versions/<版本>/documents/全文/`：按原资料路径组织的网页内嵌文字，每份保留关联问题；同源文字相同才去重，不同文字全部保留，标注完整性未核实。
- `versions/<版本>/documents/问答/`：网页整理要点、分类、标签、来源及全文文件关联。
- `manifest.json`：完整标记、条目/来源数量、文件指纹、采集时间及网页日期。
- `page.html`、`dataset.json`：网页快照与结构化内容，用于追溯，不进入检索。
- `CURRENT.json`：原子发布的当前版本指针。
- `status.json`：最后结果、下次采集时间。

网页“全文”字段可能包含节选或来源标注，不保证原始 PDF/Office 文件中的图片、表格版式及所有内容已被网站正确提取。此次直接解析网页中的 JSON 数据，不执行网站脚本。源资料路径只是来源记录，采集器不会读取这些磁盘或 SMB 路径。网页整理答案明确标注内容类型，不视为已经核实的工程事实。

文件名包含可读资料名或问题标题和完整 SHA-256，过滤非法字符并限制标题长度，避免路径符号、同名或排序变化导致错误导入。只有完整校验通过才发布新版本；条目或来源数量较上一版减少超过 20% 时拒绝自动发布，保留旧版本并排查网站变化。

## Docker 部署

在服务器的现有 Compose 目录执行（先完成数据库、原文件、密钥及配置备份）：

```bash
mkdir -p handbook-data
docker compose -f docker-compose.yml -f compose.handbook.yaml build handbook-collector rag-worker rag-core
docker compose -f docker-compose.yml -f compose.handbook.yaml up -d rag-worker rag-core handbook-collector
docker compose -f docker-compose.yml -f compose.handbook.yaml logs --tail 50 handbook-collector
```

`compose.handbook.yaml` 是增量配置，不能单独取代现有服务器 Compose。保留现有 `RAG_LOCAL_SOURCES` 映射中的其他来源；示例包含 `engineering-handbook`。采集目录必须允许采集器写入，Worker 只读挂载。

本次服务器已经将采集服务和只读挂载合并到现有 `docker-compose.yml`，日常在 `/opt/zhiku-rag/deploy` 执行 `docker compose` 即可，不必再次叠加配置。独立网络显式使用服务器现有 DNS 8.8.8.8；其他环境可以设置 `HANDBOOK_DNS` 为实际可用地址。本次下次计划采集为北京时间 2026-10-19 02:00。

可手动执行一次采集：

```bash
docker compose -f docker-compose.yml -f compose.handbook.yaml exec handbook-collector python -m collectors.engineering_handbook.collector --once
```

采集器使用文件锁，手动执行与定时执行不能同时发布。需要代理时仅给采集器设置 `HANDBOOK_PROXY`；不要填写容器无法访问的宿主机 localhost 地址。

## 知识库配置

1. 新建专用知识库“工程部手册”。
2. 在“目录同步”新建任务，来源类型选择“本地只读目录”。
3. 本地来源标识填写 `engineering-handbook`，目标选择专用库根目录。
4. 点击“测试连接”，确认已发布版本可访问。
5. 选择“固定间隔”，填写 1 小时，启用定时；先执行一次并检查执行记录。
6. 再执行一次，确认未变文件全部跳过。

不能把本地目录直接指向知识库 `uploads/` 或数据库目录。普通本地目录也可通过服务器受控映射登记，但完整版本目录必须使用 CURRENT/manifest 协议。

新库只提供逻辑隔离。拥有全部知识库权限的 MCP Key 能读取它；如需工程部专用范围，应创建或配置限定库 Key。此次部署不改变已有 OpenClaw Key 的授权配置。

## 故障与回滚

先分别检查采集容器的 `status.json` 与知识库同步执行记录。采集成功不等于索引成功，容器运行也不等于已完成资料导入。

网站布局变化、缺少全文、计数不一致、网络故障都不得发布空目录。索引失败保留旧原文与旧向量。版本历史不自动删除，可将 CURRENT 指向历史完整版本后重新同步；恢复旧程序时须配套恢复备份数据与配置，避免新任务类型不兼容。
